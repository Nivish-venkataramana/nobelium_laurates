# API Reference

Full interactive documentation (OpenAPI/Swagger) is auto-generated by
FastAPI and served at `http://localhost:8000/docs` when the backend is
running. This document is a quick reference; the live `/docs` page is
authoritative for exact request/response shapes.

## Health

| Method | Path | Description |
|---|---|---|
| GET | `/health` | Liveness check. |
| GET | `/ready` | Readiness check; verifies the database connection. |

## Projects

| Method | Path | Description |
|---|---|---|
| POST | `/api/projects` | Create a project. |
| GET | `/api/projects` | List all projects. |
| GET | `/api/projects/{id}` | Get a project. |

## Applications

| Method | Path | Description |
|---|---|---|
| POST | `/api/applications` | Register an application under a project. URL is validated against the SSRF policy before it is accepted. |
| GET | `/api/applications?project_id=` | List applications, optionally filtered by project. |
| GET | `/api/applications/{id}` | Get an application. |

## Discovery

| Method | Path | Description |
|---|---|---|
| POST | `/api/discovery` | Crawl the given URL, build the `ApplicationModel`, and store a new `ApplicationSnapshot`. Runs inline (async) since a single discovery is fast; returns the model directly. |

## Test Cases

| Method | Path | Description |
|---|---|---|
| GET | `/api/tests?application_id=` | List test cases for an application. |
| GET | `/api/tests/{id}` | Get a test case with its steps and assertions. |
| POST | `/api/tests/{id}/run` | Queue a run scoped to just this one test case. |

## Runs

| Method | Path | Description |
|---|---|---|
| POST | `/api/runs` | Queue a new run (`{"run_id", "status": "QUEUED"}`). Body controls whether discovery/generation run and the max tests. |
| GET | `/api/runs?application_id=` | List runs. |
| GET | `/api/runs/{id}` | Get a run's current status/counters/quality score/AI explanation. Poll this for progress. |
| POST | `/api/runs/{id}/cancel` | Cancel a non-terminal run. |
| POST | `/api/runs/{id}/rerun` | Create a new run with the same configuration as a previous one. |
| GET | `/api/runs/{id}/results` | Per-test-case results for a run. |

## Healing

| Method | Path | Description |
|---|---|---|
| GET | `/api/healing-events?run_id=&test_case_id=` | List healing events, optionally filtered. |

## Example: full demo flow via curl

```bash
# 1. Create a project
PROJECT_ID=$(curl -s -X POST localhost:8000/api/projects \
  -H 'content-type: application/json' \
  -d '{"name": "Demo Shop"}' | jq -r .id)

# 2. Register the demo app
APP_ID=$(curl -s -X POST localhost:8000/api/applications \
  -H 'content-type: application/json' \
  -d "{\"project_id\": \"$PROJECT_ID\", \"name\": \"Demo Shop\", \"base_url\": \"http://demo-app:5050\"}" \
  | jq -r .id)

# 3. Kick off a full run: discover, generate tests via Groq, execute
RUN_ID=$(curl -s -X POST localhost:8000/api/runs \
  -H 'content-type: application/json' \
  -d "{\"application_id\": \"$APP_ID\", \"run_discovery\": true, \"run_generation\": true}" \
  | jq -r .id)

# 4. Poll for completion
curl -s localhost:8000/api/runs/$RUN_ID | jq
```
